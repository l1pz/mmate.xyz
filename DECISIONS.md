# Decisions (settled; ask before changing)

| Date | Decision | Why |
|------|----------|-----|
| 2026-10-02 | TypeScript + Vite, no frameworks | Types catch AI mistakes; zero runtime cost |
| 2026-10-02 | Biome for lint/format, Vitest for tests, all behind `npm run check` | One command tells the AI whether it broke something |
| 2026-10-02 | ASCII art is bundled via `import.meta.glob` from `src/ascii-art/` (no fetching); every HTML page is listed in `vite.config.js` | Runtime fetching looped forever in dev (Vite answers missing files with index.html) |
| 2026-10-02 | Card text goes through `toHtml()` which escapes everything; links are placed by position | Old string-replace broke on `<`, `&` and duplicate words |
| 2026-10-02 | Features are folders `src/features/<name>/` exporting one object (`id`, `card()`, optional `page`); features never import each other, shared code in `src/core/` | Keeps each AI session inside one folder (see ARCHITECTURE.md) |
| 2026-10-02 | Oracle is a broadcast, not a chat: one self-hosted small model streams its "thoughts" to all visitors via SSE; no visitor input, no paid APIs | Cost and abuse do not grow with visitors; coherence matters more than the smallest footprint |
| 2026-10-02 | Hosting: own netcup server, domain 1000110.xyz. Traefik is the only reverse proxy; site is an `nginx:alpine` container (stack `/opt/stacks/1000110-xyz`) serving a bind-mounted `dist/`. CI rsyncs `dist/` as an unprivileged `deploy` user restricted by rrsync to that directory (`deploy/setup-server.sh`) | No second proxy; deploy is a file sync; a leaked CI key cannot reach Docker |
| 2026-10-02 | `.gitattributes` forces LF line endings everywhere | Windows CRLF checkouts made `npm run check` fail locally while CI passed |
| 2026-10-02 | Font is DejaVu Sans Mono (self-hosted woff2 in `public/fonts/`, full glyph set; replaces Space Mono from Google Fonts). It has box drawing, block elements and geometric shapes but NO braille or legacy computing symbols; GNU Unifont (subset, 12 KB) was tried and rejected: the bitmap look is bad in a browser. JGS (`jgs7`, 14px) was tried and rejected: perfect for the ASCII art but hard to read as text; it covers every glyph we use, so it stays in `public/fonts/` for art-only use. No font toggle. One font for the whole grid, because a fallback font has other glyph widths and breaks alignment | Space Mono lacked box drawing, so `single/double/rounded` borders were misaligned; self-hosting also removes the Google request |
| 2026-10-02 | `<noscript>` cards are generated at build/dev time from `src/cards.ts` by `plugins/noscript-cards.js`, never written by hand; the border is hardcoded once in `buildHomeCards` | One source for both versions; the hand-written copy had to be edited for every card change |
| 2026-10-02 | The binary footers stay hidden easter eggs: no decode animation, no hints, no hover/click reveal | The charm is that visitors find and decode them themselves |
| 2026-10-02 | Cards use the `rounded` border, hardcoded in `src/index.ts`. Styles (none, retro, ascii, single, double, rounded) stay as data in `src/borders.ts`; `<noscript>` cards carry the same rounded frame. The toggle (key `b`, localStorage setting) was built, tried and removed | The user wants one fixed look for now; re-adding a toggle is easy because styles are data |
| 2026-10-02 | Blog frontmatter is parsed by a small hand-written parser (`key: value` and inline `[a, b]` only, throws with the filename on bad input); posts are bundled at build time via `import.meta.glob` from `src/features/blog/posts/` | Zero runtime dependencies; `gray-matter` needs Node `fs`/`Buffer` and is unmaintained; richer YAML can be swapped in later behind `parsePost` |
| 2026-10-09 | Card footers (hidden binary messages) use `card.drawFooter(text)`: fixed 4 lines at the bottom, padded with spaces to 16 characters, throws if too long or overlapping content | Footers were placed with hand-counted `emptyLine`s and drifted (the blog card had 3 lines, not at the bottom) |
| 2026-10-09 | Cards are for the home grid and widgets only. Blog posts are read on a full page styled as a pager (72ch column, native scroll, fixed status line with the progress meter, hash routing `/blog/#slug`), rendered by a small hand-written Markdown-to-HTML converter | Reading long text in a 41x32 card is painful; a normal page keeps selection, find, links and phone scrolling while the look stays terminal-like |
| 2026-10-09 | Card colors are a per-cell style layer in the card engine (`CardStyle` names, `<span class="c-NAME">` in `toHtml()`), colored by theme variables in `card.css`; titles yellow, borders and footers gray, art accents per card. Home keys: h/j/k/l always, arrows only once a card is focused, so plain scrolling keeps working | One engine feature colors the JS cards and the generated `<noscript>` cards alike; hijacking arrows from the start would break keyboard scrolling on the one-column mobile layout |
| 2026-10-10 | Design system (DESIGN.md): one shell (crumbs, man header, `$` prompt lines, end prompt with cursor, bottom status line) for every page, phone first (40 columns, fluid font under ~400px, 44px tap targets, safe area, short window names). Card titles are commands (`$ cat about`) with a dim `$`; cards are widgets inside the shell | The home page and the blog felt like two different sites; one shared vocabulary lets each page keep its own content |
| 2026-10-10 | Home card grid columns are exactly `41ch` wide and the home wrapper is sized from the column count, not `fit-content` | `fit-content` followed the longest header line, so the header was wider than the cards on phones |
| 2026-10-10 | Every page is built by one frame, `renderPage` (crumbs, man header, `$ command`, body, optional secret, end prompt), and listed once in `src/core/site.ts`; the status line (site windows left, clock and progress right) and the keys (1-9, j/k, g/G, b/Esc) are shared too. Tests (`assertShell`, site map vs `vite.config.js`, built pages) fail when a page skips a part | Home, blog index and post each assembled the shell by hand and drifted (missing header and end prompt, different status lines); a page can now only supply its body |
| 2026-10-10 | The home page is a session (one command per section), not a grid of cards. The card engine, its colors and tests stay as a toolkit for later widgets; the home cards, blog card, card keyboard navigation and card windows were deleted (git history keeps them) | The 41 x 32 tile forced a fixed width, equal weight and centered text, so home felt unlike the blog |
| 2026-10-10 | Hidden messages are a shared `secretBlock` (dim binary, 4 bytes per line, aria-hidden), in the frame's `secret` slot or per section; blog posts may set `secret:` (max 32 characters). No hints, no decode | Keeps the easter eggs from the cards on every page and lets each post hide its own |
| 2026-10-10 | The home page imports all blog posts into its bundle (it lists the newest five with word counts) | Simple for a few posts; replace with a generated post index (the RSS task makes one) when the blog grows |
